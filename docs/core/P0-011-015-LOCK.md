## P0-011 — source vs sourceType vs channel

| Field | Meaning | Examples |
|-------|---------|----------|
| **source_channel** | Interface that submitted the op | `ui` \| `api` \| `import` \| `migration` \| `system` |
| **source_type** | Business provenance of the fact | `manual` \| `bank_statement` \| `broker_statement` \| `exchange_api` \| `opening` \| `correction` \| `csv` \| … |
| **source_reference** | External/source identifier | file name, statement id, API tx id, batch label |

`fin_operations.source` is **LEGACY alias of source_channel** — writers must set `source_channel` (and copy to `source` for compatibility).

Journal line `source_type` historically mixed channel values; new code prefers channel on operation and business provenance on domain/import rows.

## P0-012 — Tax two-entity model

```
tax_events  = economic/accounting tax facts (gain recognition, withholding event, adjustment)
tax_records = user-facing obligation / filing / payment state for a period
```

Relationship:

```
tax_record 1 —— 0..N tax_events   (via linked_tax_event_id and/or period_key join)
payTax operation → tax_records.payment_operation_id + status=paid + optional tax_event payment leg
```

Amounts:

| Need | Home |
|------|------|
| Event tax amount | `tax_events.amount` |
| Obligation total / paid | `tax_records.amount_due` / `amount_paid` |
| Due date | `tax_records.due_date` |
| Payment op | `tax_records.payment_operation_id` |
